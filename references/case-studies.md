# 已有反馈支持的经验

## 九宫格“不想上班”

初始九帧在转头、遮挡和探头处跳跃，简单交叉淡化产生双影。补充真实中间角度与遮挡姿势后，得到用户接受的 65 个时间轴帧、58 个独立画面版本。结论是对明显姿势缺口补图有用，不是 65 帧具有普遍优势。曾出现生成网格截断和重复帧，因此网格完整性必须实际查看。未做微信发送实测。

## 古装角色开心摆手（用户于本任务中认可）

### 失败信号与处理

| 用户反馈/观察 | 调整依据 |
| --- | --- |
| 感觉鬼畜、调速后仍不流畅 | 速度只是一个变量，还需检查姿势间距、运动对齐和转向速度 |
| 紫色背景明暗变化不舒服 | 从选定人物原帧分离背景，使用同一张底图，而不是每帧重画背景 |
| 只有手动，头和表情没动 | 动作参考应分析整个人物的配合，不能只抠出一只手做摆动 |
| 嘴巴变形，要求回到舒缓版 | 恢复用户指定的原 GIF；保留其原始人物像素，背景处理不顺带重绘脸 |
| 扩到 60 帧后仍不连贯 | 原来的等时姿势连接和块状补间仍有局部变形；帧数不代表平滑度 |

### 本次获得认可的版本

在原来四个相近姿势间计算双向稠密光流，先按运动对齐两端，再合成中间帧；采用余弦往返进度，使动作在两个转向点逐渐减速、再加速。对确认始终可见的背景区域恢复同一像素，统一全局调色板。用户反馈：“OK这次做的不错了”。

- 推荐版：240×240，60 时间轴帧，31 个不同解码画面，30 ms/帧，每轮 1.8 秒，`loop=0`。
- 快慢对照采用相同画面顺序，分别 20 ms/帧（1.2 秒）和 40 ms/帧（2.4 秒）。
- 推荐版 2,161,521 字节；指定固定背景区域最大像素变化为零。往返有姿势复用，不能宣传为 60 张新绘制动作。
- 已完成重新解码、静态联系表检查和用户认可；没有微信保存/发送实测记录。

这些数字是案例数据，不是默认交付指标。光流更换和缓动调整是同时进行的，不能从这次反馈推断哪一个单独贡献更大。该方案适用于小幅、近似可逆的动作；大转头、强遮挡、手形或嘴型拓扑变化仍可能变形，需要真实姿势或不同动作设计。对称往返也不应推广到所有笑、眨眼、回弹等表演。

## 下次首版优先做什么

先读参考动作的完整配合，锁定用户接受的角色与镜头；背景需要稳定时从开始就分层。针对姿势差异选择补图或运动补间，在总时长内安排缓动，再制作整段。首版交付前重点看脸、手、转向和循环接缝。目标是减少可避免的返工，不承诺任何素材都能一次通过。
